PAYMENT GATEWAY & SUBSCRIPTION FLOW - COMPLETE DOCUMENTATION
==============================================================

## COMPLETE USER & ADMIN FLOW:

### USER REGISTRATION & PAYMENT FLOW:
1. User registers at /register
   - Username created in `users` table
   
2. User clicks "Get Subscription" button on login page
   - Redirects to /payment
   
3. User submits payment form with:
   - Email (must be valid format)
   - Full Name
   - Mobile Number (10 digits)
   - UTR Number (from UPI transaction)
   
4. Payment saved to database with:
   - Status = PENDING (waiting for admin approval)
   - Payment Date = Current timestamp
   - All user details stored
   
5. User navigates to /dashboard (after normal login)
   - System checks: paymentService.hasValidSubscription(email)
   - If NO payment or status != APPROVED:
     → Redirects to /subscription_invalid page
     → Shows specific reason (PENDING, REJECTED, or EXPIRED)

### ADMIN PANEL FLOW:
1. Admin clicks "Admin Login" on login page
   - Username: admin
   - Password: admin@123
   - Auto-initialized on first startup
   
2. Admin views /admin/dashboard
   - Shows ALL pending payments in table
   - Displays: ID, User Name, Email, Mobile No., UTR, Status
   
3. For PENDING payments, Admin can:
   - APPROVE: Select subscription start & end dates
   - REJECT: Add optional rejection notes
   
4. Admin actions:
   - APPROVE: Payment status = APPROVED + dates set
   - REJECT: Payment status = REJECTED + notes stored

### USER ACCESSES DASHBOARD WITH REJECTED PAYMENT:
1. User logs in with email/password (works - different from Payment)
2. Tries to access /dashboard
3. System calls: paymentService.hasValidSubscription(email)
4. Payment found with status = REJECTED
5. Displays: /subscription_invalid page with:
   - Status: "REJECTED"
   - Rejection reason (if provided by admin)
   - Button to "Re-submit Payment"
   - Button to "Contact Admin"

## SUBSCRIPTION VALIDATION LOGIC:
==================================

public boolean hasValidSubscription(String email) {
    1. Find payment by email
    2. If no payment → return FALSE
    3. If status != APPROVED → return FALSE
    4. If subscription end date passed → return FALSE
    5. If all checks pass → return TRUE
}

This means user is BLOCKED if:
- ✗ No payment submitted yet
- ✗ Payment is PENDING (awaiting admin approval)
- ✗ Payment was REJECTED by admin
- ✗ Subscription dates have expired

User can ACCESS if:
- ✓ Payment is APPROVED
- ✓ Current date is between start & end dates

## DATABASE CHANGES:
====================

### NEW TABLE: payments
Columns:
- id (Primary Key)
- email (User email)
- userName (User's full name)
- mobileNumber (10 digits)
- utrNumber (UPI transaction ID)
- status (ENUM: PENDING, APPROVED, REJECTED)
- paymentDate (When payment was submitted)
- subscriptionStartDate (Set by admin on approval)
- subscriptionEndDate (Set by admin on approval)
- adminNotes (Rejection reason)
- approvalDate (When admin approved/rejected)

### NEW TABLE: admins
Columns:
- id (Primary Key)
- username (Unique - default: "admin")
- password (Encrypted - default: "admin@123")
- name (Admin name)
